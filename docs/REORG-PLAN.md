# moca documentation reorganization plan

> Provenance: audited against `upstream/main` b009079 on 2026-10-12, after PRs #485 and #486 merged (ADR-0041 Knative/KEDA deprecation; P6-first README/CLAUDE.md flip). Line numbers refer to that tree. Items marked _(unverified)_ were not confirmed. Findings fixed by #485/#486 or by PR 1 (#488) are marked FIXED in 4.0.

## 1. Executive summary

- **What #485/#486 already did:** Knative/KEDA is formally deprecated (ADR-0041, Accepted, 2026-10-11; security/breakage fixes only; removal **no earlier than end of October 2026**, once remaining users confirm migration); `docs/migrating-from-knative.md` exists; banners on all `deploy/knative/` guides, three Knative demos, setup scripts, Makefile, Dockerfile; runtime warning; README and CLAUDE.md flipped to a P6-first, compose-first narrative. So the original "add a deprecation page and banners" PR 1 is **done**.
- **Top remaining problems (as of b009079; PR 1 / #488 fixes the registry and link parts of (2) and (3), see 4.0):** (1) No docs structure beyond the README: no install-path chooser, config/env reference, operations docs, API guide or docs index; ~900 `SH_*` hits scattered across 72 files. (2) Status honesty gap: ADR-0041 and the README call P6 the primary runtime while the registry still shows P6/P6.1 "design (proposed)", ADR-0034/0037 "Proposed", no release notes mention P6/P4, and no per-path maturity labels exist; the README roadmap still omits P4/P6/MU/MI/RA. (3) Link and registry rot: 24 broken relative links (20 to `docs/research/` outside the repo), 11 unregistered specs, orphaned user-facing docs (`docs/context-service.md`, OpenAPI yamls), stale executive overview and experiment results, no docs tooling (link check, lint, site).
- **Case determination:** the repo now supports a **hybrid, closest to Case (i)**: P6 is the declared default path and Knative is Legacy with a dated deprecation, but P6/P4 are not yet labelled Stable anywhere and **async-leaf (archetype A) and cron (archetype C) have no P6 equivalent**. Docs treat P6 as _Primary (Preview-labelled until the maintainer confirms Stable)_, Knative as _Legacy_.
- **Time-sensitivity:** the earliest removal is ~2.5 weeks away. Do **not** move Knative docs into a new `legacy/` tree; leave them in place with their banners and delete them in the removal PR.
- **Recommended structure (small):** `docs/` with `get-started/`, `concepts/`, `guides/`, `reference/`, `operations/`, `project/` (index over existing `specs/`, `adrs/`, `notes/`, `demos/`); `docs/migrating-from-knative.md` stays the single deprecation/migration page (extended, not duplicated). Specs/ADRs stay at their paths.
- **First PR (revised):** docs hygiene on `upstream/main`: fix the 24 broken links, reconcile registry/ADR statuses and register the 11 specs, add the missing migration-guide content, label remaining unbannered legacy docs. No moves.

### 2.2 Principles

1. **Split by reader task** (tutorial / how-to / reference / explanation): diataxis.fr; Kubernetes page-type templates, kubernetes.io/docs/contribute/style/page-content-types/.
2. **Separate entry points for user, operator, developer:** Argo CD (argo-cd.readthedocs.io/en/stable/), KServe Admin vs Developer guides.
3. **Fan install out by platform/mode behind one landing page:** vLLM (docs.vllm.ai/en/latest/getting_started/installation/), Istio sidecar vs ambient, Flux per-host bootstrap.
4. **A dedicated Operations area:** Istio Operations, KEDA "Operate".
5. **Policy pages inside the docs nav** (release, versioning, feature lifecycle): Crossplane Feature Lifecycle, Backstage versioning policy.
6. **Generated/precise reference kept apart from narrative:** Kubernetes, Flux components, Modal SDK/CLI reference.
7. **Put design records beside, not inside, user docs:** vLLM `design/`, Kata `design/`, gVisor Architecture Guide.
8. **Agent-readable docs** (`llms.txt`, per-page markdown): E2B, Kagent, OpenHands. Optional for moca; cheap with MkDocs.

### 3.4 Timeline and support level

- **ADR-0041 (Accepted, 2026-10-11; `docs/adrs/0041-deprecate-knative-keda-deployment.md`):** deprecated = Knative Service, KEDA ScaledJobs, `KubectlTransport`/pod-exec sandboxes, `deploy/knative/`. Not deprecated = `deploy/k8s/` (ADR-0037), container sandbox tier, shared code in `packages/knative-server` and the non-K8s half of `packages/k8s-sandbox`. **Support:** security and breakage fixes only, no new features. **Removal:** no earlier than end of October 2026 and only once remaining users confirm migration (commit 9fcd3d7 shortened this floor). Capacity under P6 scales by adding/sizing process-manager pods; loss of scale-to-zero is an accepted cost. Supersedes ADRs 0002/0003/0004/0009/0015/0018/0019/0023; softer wording for 0017/0025/0027 (index shows "Superseded by 0041" for all eleven, with caveats in the 0017/0025/0027 files).
- **Still not defined:** an actual removal date/version; process to confirm "remaining users migrated"; **async-leaf (archetype A) and cron (archetype C) have "no P6 equivalent yet"** (ADR-0041 follow-ups; ADR-0034 line 128; README 255/257/259-263; migration guide row 6). Demo rewrites onto P6 are owed (demos only bannered). `knative-server` rename and `sandbox-transport` extraction explicitly out of scope. #338 (P4 workspace TTL data loss) open, "not gating".
- **Executed signals:** banners on all six `deploy/knative/` guides (wording: "Deprecated 2026-10-11 (ADR-0041)... security and breakage fixes only... removal no earlier than end of October 2026... P6 is the primary way to run moca sessions: see Migrating off the Knative/KEDA deployment"), demo banners ("This demo runs on the deprecated Knative/KEDA path... see `vm-multi-user-demo.md`"), setup-script stderr notices, Makefile/Dockerfile/`build.yaml` labels, runtime warning (`packages/knative-server/src/deprecation.ts`; fires only when `K_SERVICE`/`K_CONFIGURATION`/`K_REVISION` set, or unconditionally in `leaf-job.ts` and `cron-dispatch.ts`; P6 worker deliberately silent, pinned by `test/deprecation.test.ts`).
- **Multi-user:** `docs/specs/2026-09-28-moca-multi-user-isolation-design.md:824`: no multi-user mode on the Knative path.
- **Releases:** tags v0.4.0-v0.5.3 and a rolling `mocactl-edge`; **no release notes, changelog or CHANGELOG file** say P4/P6 shipped.
- **Contradiction (resolved by PR 1 / #488: P6 and P6.1 now "implemented", ADR-0034/0037 Accepted; ADR-0035/0040 stay Proposed):** ADR-0041/README say P6 is the primary runtime; registry still says P6 and P6.1 "design (proposed)" (P6.2/P6.3 "implemented", P4 "design ✅"); ADR-0034 and ADR-0037 still "Proposed".

### 3.5 CLIs

`mocactl` (`packages/mocactl`; installer `scripts/install-mocactl.sh`, Node 22+, `MOCACTL_VERSION`, `MOCACTL_INSTALL_DIR`; subcommands incl. `run`, `promote`, `bundles delete`, `credentials`); older harness `pnpm promote` + `deploy/claude/commands/promote.md` (`SH_HARNESS_DIR`); `vmpoolctl` (Go, diagnostic, no install path); setup scripts per `deploy/*`. Subcommand/flag list to be generated from `mocactl --help` when writing the reference.

### 3.6 Terms under P6/P4

`session`, `turn` unchanged in meaning (P6.3 adds tier + affinity as session properties). `sandbox`: boundary changes (pod, then microVM per Exec), contract (`Attach`) unchanged; "sandbox-0" is a Knative-path name. `leaf`: used as batch/queued work; its meaning does not change under P6. The `--role=leaf` worker role is reserved by the P6 spec (§3.3) but not implemented (the worker exits 2 for any role but `turn`). The glossary now defines leaf and the other runtime terms (PR 5a).

- **Case (i) p4/p6 released and default:** `get-started/*` backend pages become [S]; Knative banners stay until removal. Promotion = flip front-matter labels and update the migration guide's status log.
- **Case (ii) designed/implemented but not default:** the previous situation (Knative runs the old Quick Start, deprecated; P6/P4 Preview).
- **What the repo evidence supports now (post-#485/#486): a hybrid, closest to (i).** P6 is declared primary by ADR-0041 and the README; Knative is deprecated with dated banners and a removal floor; but no document labels P6/P4 Stable, the registry says P6/P6.1 "design (proposed)", the Compose path is "trial", P4 has open limits (#277, #274, #338), and archetypes A/C exist only on the deprecated path. Treatment: P6 paths are labelled **Preview** until the maintainer decides what Stable means (Q1), but they are the _default recommendation_ in README/get-started; Knative is **Legacy**. When Q1 is answered, promotion is a label flip; the tree in 5.2 does not change.

### 6.4 Rules for splitting architecture-independent content

1. Concepts, HTTP API, leaf/envelope, CLI, security model, human gates never mention Knative/KEDA except in a clearly marked "Implementation notes: Legacy" box.
2. Substrate-specific facts go in a per-substrate table (one row per path) instead of prose.
3. Knative how-tos keep only install/operate steps; extract `README-worker.md` and `README-authbridge.md` concept content into `concepts/` and `reference/`.
4. Env vars documented once in `reference/configuration.md` with a "Applies to" column.
5. Archetype page states availability per substrate (sync, human gate: all; async fan-out: KEDA legacy, P6 round two; scheduled: CronJob legacy, P6 timer round two).

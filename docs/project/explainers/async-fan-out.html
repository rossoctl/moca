MOCA · PR #696 · ADR-0047

P6 async fan-out

A drain loop inside the ordinary turn worker — how N leaf turns are submitted, queued as bare ids, drained under the same admission budget as interactive turns, granted credentials only at dequeue, and recovered after a crash. Step through the mechanism, then read the decisions behind it.

interactive turn async leaf control-plane mint failure path

The decision

Async fan-out is a drain loop inside the ordinary turn worker, taking its slots from the same TurnCounter as interactive turns. The queue carries a turn id and nothing else; the leaf's credentials are minted when a worker claims it.

Shape of the answer

One queue, one trust model

mocactl, an LLM coding agent and a controller all enqueue through the same authenticated, owner-scoped API. The archetypes spec's deterministic non-LLM orchestrator no longer holds (#378), so every property must survive a misbehaving client.

The data-plane route stays removed

/runs {async:true} is unauthenticated when SH_REQUIRE_AUTH is off — the second trust model this design rules out. Two submission paths means every safety property is enforced twice and can diverge once. A controller holds a service-account credential instead (#687).

Shared admission, no headroom

No supervisor change: onChange already sends the load IPC and reconcile already treats the worker as authoritative. Dedicated --role=leaf workers and a second counter both create two capacity budgets that must be reconciled.

No credential in the queue

At claim the worker presents its own identity plus the turn id; the control plane resolves a credential name and mints the two MI1 grants. "Turn start" for turn_exp is dequeue, not enqueue.

turn_exp can only tighten

Clamped at mint: dequeue + min(caps.wallClock ?? 1800s, 1800s). Hour-long turns are an operator decision — raise the ceiling — not a caller's. A caller asking for more is clamped, not refused.

Abandon without acking on drain

The in-flight leaf is left pending for XAUTOCLAIM; the slot is released so awaitIdle exits early. A 1800 s leaf cannot finish in a 20 s grace window, and nobody is waiting on an async leaf — redelivery beats aborting.

Four findings worth a reviewer's attention

  1. 1

    turn_exp is specified in MI1 §6.1 and implemented in no TypeScript. Expiry today is always exp = iat + ttlSeconds. #388 is larger than it reads, and this is where the M1/M2 split comes from.

  2. 2

    The claim heartbeat, without which every real leaf double-runs. minIdleMs is 90 s against a MOCA_TURN_MAX_S of 1800 s: a leaf running past 90 s goes idle in the PEL while still running, and a peer's XAUTOCLAIM reclaims it — idempotent in result, double-spent in budget and sandboxes. The removed leaf-job-runner.ts had it solved (touch every 30 s, cleared in a finally), which is why the restore scope names that file.

  3. 3

    All three synchronous leaf aliases occupy no slot today. /runs, /run-leaf and /v1/runs are not in TURN_PATHS. Bringing them into the counter fixes a pre-existing over-admission defect — and is a behaviour change on a live path: deployments at their ceiling will see 429s they previously would not.

  4. 4

    The consumer group had no lifecycle on P6. The removed drainer reaped once at process start and GC'd idle consumers so KEDA could scale to zero; neither trigger survives. Reclaim becomes periodic and armed by every worker, keyed on moca-${HOSTNAME}-w${SH_WORKER_ID} — stable across an in-place restart, unique per live worker.

Delivery in three milestones

M1

A working drain, single tenancy

Queue restored; drain loop in the worker; quota, status read, queued-only cancel. Gated to MOCA_TENANCY=single as a dated conditional refusal — a stated condition with a lifting criterion, not an omission.

M2

Multi-tenant

turn_exp implemented (MI1 §6.1), full grant-at-dequeue with both audiences (#388), and the tenancy gate lifts.

M3

deploy/k8s

Manifests, Kind and OCP overlays, setup.sh, and a queued-leaf smoke test (#688).
